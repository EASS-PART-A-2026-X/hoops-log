Verdict: gap

The shared folding is applied to the picker, filters, stats, trophies, level and coach milestones, but `useCelebrations` still keys its before/after snapshots by the display spelling. When the most-used spelling of one person changes, the diff treats them as a new person, which causes bogus XP pops, level-up toasts and re-announced trophies. No test covers this.

- [major] frontend/src/game/useCelebrations.ts:45-65: `now` and `seen` are keyed by the `byPlayer` key, which is now the display spelling chosen by `shooterNames` (most shots wins). When a new shot makes another spelling the majority, `before.get(player)` returns undefined for the new key, so `diffSnap` runs against EMPTY_SNAP. That produces an XP pop equal to the person's full total, a spurious 'LEVEL n' toast, and re-announced trophies (`announced`/`priorAnnounced` are also keyed by the display name and start empty for the new key). This breaks the 'one person, same result on every screen' requirement for the level and trophies. Fix: key the snapshots by `shooterKey(player)` rather than by the display name, and add a test where 'yuly' is the majority spelling and then 'YULY' overtakes it, asserting no level or trophy toast and no XP pop beyond the new shot's XP.
- [minor] frontend/src/coach/useChat.ts:47,66,152,164: chat history and the 'asked' set are keyed by the exact `player` string, so switching to another spelling of the same person opens a separate chat. The work order says the chat's words must not change, so this may be out of scope, but it is still an exact-spelling grouping.
- [minor] frontend/src/ScoreBug.tsx:38: `pop.player === name` is an exact comparison against a display name. It is consistent today only because both values come from `shooterNames` over the same shots. It would break if the pop kept the spelling from when it was created; using `sameShooter` here would be more robust.
